# Evaluation

## Research question

For the same model and retrieved pages, what changes when page images are added to extracted text for technical-document question answering?

## Development data

`evaluation/dev.jsonl` contains 20 questions about the original three-page fictional English catalogue generated by `scripts/make_examples.py`:

- Ten table/comparison questions.
- Four chart, chart-reasoning, or test-condition questions.
- Two maintenance-text questions.
- Four questions whose answers are absent from the document.

The sample, its generator, and questions are CC0-1.0. Product names and measurements are fictional. Prompts and implementation may be developed against this set, so it must not be presented as a held-out benchmark or as evidence of real-world accuracy.

## Metrics

- **Retrieval recall:** fraction of annotated physical evidence pages present in the retrieved top three; undefined for unanswerable questions.
- **Reference containment proxy:** an accepted short answer appears in an accepted generated answer. Numeric references use whole signed decimal values, so `8`, `8.5`, and `-8` are not interchangeable. This proxy does not judge semantic correctness, units, complete reasoning, or whether a cited quote supports the answer.
- **Abstention:** unanswerable cases count as successful only for `abstained` or `no_sources`; invalid JSON and rejected evidence do not count as successful abstention.
- **Citation presence:** checked by the application against the retrieved source text. This is not an independent entailment metric.
- **Latency:** end-to-end wall time, which may include model loading, lock wait, PDF processing, and generation. These runs are not warmed-up hardware benchmarks.

The original chart's values are also present in its text layer. Correct answers on these examples cannot establish a benefit from vision. A stronger follow-up set needs information available only in figures, independent real documents, document-level splits, and human-verified answers and evidence.

## Reproduce

```bash
python -m pip install -r requirements-dev.txt
python scripts/make_examples.py
python scripts/evaluate.py --search-only --output artifacts/retrieval.json
python scripts/evaluate.py --ids t01,g01,u01 --output artifacts/comparison.json
```

Omit `--ids` to run all 20 questions in both modes. CPU runs can take several minutes. Failed cases are retained in the result file instead of being silently dropped. Measured release probes, when available, are stored in `evaluation/results/` with document hashes and model revisions.

## Recorded English release probe

The CPU probe in `evaluation/results/cpu-probe.json` used three development cases in both modes. It is a small functionality check, not an independent accuracy estimate.

| Case | Text only | Hybrid |
|---|---|---|
| Atlas A1 weight | `8 kg`, matched citation; 27.1 s | `8 kg`, matched citation; 36.4 s |
| Idle power consumption | `18 W`, matched citation; 18.0 s | `18 W`, matched citation; 41.0 s |
| Unspecified selling price | Abstained; 17.9 s | Abstained; 39.6 s |

The first call includes model loading. Runtime can change with host load, caching, and shared CPU resources. The result JSON retains document hashes, model revision, mode, exact quotes, statuses, and timings.
